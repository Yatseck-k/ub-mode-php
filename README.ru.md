# ub-mode-php

[English version](README.md)

Независимый навык агента для последовательной работы с кодом. Он работает с тестами проекта и ручным ревью; установленные анализаторы добавляют измеримые результаты. Навык вызывается как `ub-mode` и не имеет обязательных runtime-зависимостей. Необязательный анализатор `ub-cdmu-php` (CDMU) — Composer-пакет для PHP 8.2+, которому не нужны Python или Docker.

Последовательность работы: **First Make it Work** — небольшие изменения, поведенческие тесты и границы; **Then Make it Right** — причины ошибок, сложность, дублирование, мутации и рефакторинг; **Practice** — журнал, контекст, очистка и коммиты. Каждый этап применим без анализатора.

## Установка навыка

Из этого репозитория скопируйте инструкции в каталог навыков агента. Для Codex:

```sh
mkdir -p ~/.codex/skills/ub-mode
cp SKILL.md ~/.codex/skills/ub-mode/SKILL.md
```

Для Claude Code или Cursor разместите `ub-mode/SKILL.md` в каталоге навыков соответствующего агента. Используйте `$ub-mode` или `/ub-mode` согласно интерфейсу агента. После изменения файла в репозитории повторите копирование, чтобы обновить установленный навык.

## Необязательный CDMU

Агент сначала запускает тесты проекта и просматривает изменения. Если CDMU отсутствует или недоступен, работа продолжается через тесты и ручное ревью с явным указанием недоступных измерений. CDMU никогда не устанавливается автоматически.

Установите его в PHP-проект самостоятельно. До появления на Packagist используйте GitHub или локальную копию (путь должен существовать в среде, где работает Composer, включая контейнеры):

```sh
composer config repositories.ub-cdmu-php vcs https://github.com/Yatseck-k/ub-cdmu-php
composer require --dev yatseck-k/ub-cdmu-php:dev-main
# или из локальной копии:
composer config repositories.ub-cdmu-php path ../ub-cdmu-php
composer require --dev yatseck-k/ub-cdmu-php:@dev
```

Если вы только знакомитесь с CDMU, прочитайте [краткую инструкцию](https://github.com/Yatseck-k/ub-cdmu-php/blob/main/docs/GUIDE.ru.md). Все параметры, коды выхода и контракты отчётов — в [руководстве](https://github.com/Yatseck-k/ub-cdmu-php/blob/main/docs/README.ru.md#cli).

## Что запускает агент

Из корня проекта, после его тестов:

```sh
vendor/bin/ub-php doctor --format json
vendor/bin/ub-php check --changed --format json
# Более строгая проверка дублирования при необходимости:
vendor/bin/ub-php dry --changed --threshold 0.8 --format json
```

Вне Git опустите `--changed` (с ним CDMU завершается кодом 3). Пустой набор изменений не подтверждает качество всего проекта. Агент принимает решения по JSON (`entries`, `exceeded_threshold`, `coverage`, `candidates`) вместе с кодом выхода, а не по тексту для человека:

| Код выхода | Значение |
| --- | --- |
| `0` | Успех; возможны неизвестное покрытие, предупреждения о дублировании или нарушения CRAP при отключённом `quality.fail_on` |
| `2` | Известный CRAP не ниже порога (по умолчанию 10) или известный MSI ниже минимума |
| `3` | Ошибка анализа, среды, конфигурации или отчёта (в том числе пустой полный анализ) |
| `4` | Неверный вызов |

Отсутствующий Clover — это `unknown`, а не 0% и не подтверждённый успех. Кандидаты DRY — предупреждения. Пороги не снижаются ради скрытия замечаний.

## Мутации и UML

```sh
vendor/bin/ub-php doctor --tools --format json
# Запускает тесты проекта с их обычными побочными эффектами: применять, когда это входит в задачу.
vendor/bin/ub-php mutate --changed --min-msi 80 --format json
# Статический анализ без выполнения исходников:
vendor/bin/ub-php uml --format json
# Откройте .metrics/uml.html в браузере без сервера.
```

`mutate` поддерживает Infection **0.29.14** (проверено с PHP 8.2, PHPUnit 11.5 и Xdebug) и требует POSIX/PCNTL на Linux/macOS. Без них агент сообщает, что мутационный анализ недоступен.

- Известный MSI ниже минимума даёт код 2. Неизвестный MSI без порога — WARN/0; с `--min-msi` или `mutator.min_msi` — FAIL/3, потому что обязательный порог невозможно оценить. В этом случае в stdout выводится полный JSON с `gate_evaluated: false`. Остальные ошибки engine, baseline и ввода-вывода дают код 3 и могут оставить stdout пустым, поэтому сначала проверяйте код выхода.
- После неудачного запуска может остаться прежний `mutate.json`; он не является результатом последнего запуска.
- Killed, survived, uncovered, timeout, error, syntax_error, ignored и skipped различаются; MSI и covered MSI — разные показатели.
- Отпечатки мутаций отслеживают исходники, тесты и конфигурации. Для дополнительных реальных входов используйте `mutator.input_paths`, для генерируемых тестовых данных вроде `tests/tmp` — `mutator.input_exclude`; не исключайте настоящие входы, чтобы скрыть изменения.
- История отчётов по умолчанию — пять поколений на инструмент и пять ошибочных запусков; `0` снимает лимит.

UML — статический снимок: классы, связи, текущий CRAP и, если он корректен, слой мутаций. Устаревший или недоступный слой и неизвестный CRAP считаются отсутствием доказательств. Повтор имени класса даёт WARN и узел `ambiguous`. Код `0` у UML означает успешное построение, а не прохождение quality gate. `--changed` не поддерживается.

## Происхождение

Навык следует трёхэтапной структуре [unclebob/ub-mode](https://github.com/unclebob/ub-mode), адаптированной для необязательных инструментов и PHP-проектов. Исходный навык и [Crapper](https://github.com/unclebob/crapper), [Dryer](https://github.com/unclebob/dryer), [Mutator](https://github.com/unclebob/mutator), [UML Viewer](https://github.com/unclebob/uml-viewer) — независимые upstream-проекты.
